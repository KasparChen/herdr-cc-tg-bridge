# tg-bridge v3 消息状态与不重复发送

状态 CONFIRMED
版本 v3
前版路径 `docs/PRD-v2.md`（CONFIRMED 2026-10-05，保留不改）
依据 2026-10-08 使用者反馈两件事。一是上午电脑从睡眠中醒来时，General 里连续冒出多条状态消息。二是在群里看不出 bot 有没有收到消息，分不清它在回复还是根本没收到
确认依据 2026-10-08 对话，使用者选择推荐方案（reaction 状态 + 发送超时不重试 + `/resend`），并指定了表情
定稿日期 2026-10-08

## 结论

v3 做两件事。

1. 状态消息只有一条，原地更新，不再刷屏。网络断开或电脑睡眠时，bridge 不会改发新消息；异常且连续 3 次没变化就停止自动刷新，置顶消息上有「🔄 刷新」按钮可以手动刷新。
2. 你在话题里发的每条消息，bot 都会用 reaction 标出它走到了哪一步。一条回答只发一次，发送超时不再自动重发，改为在你的消息上标 😱，需要时发 `/resend` 补发。

v2 的其余能力不变。

## 原来的问题

| 问题 | 发生了什么 | 原因 |
|---|---|---|
| General 刷屏 | 10-08 上午合盖睡眠约 20 分钟，11 点半醒来时 General 里连续出现多条状态消息并被置顶 | 置顶消息编辑失败（包括网络超时）就改发一条新的；每 30 秒一次的刷新没有防重叠，网络卡住时几十次刷新堆在一起，醒来后各自发出新消息 |
| 回答可能重复 | 网络差时同一条回答最多可能出现 6 份 | 发消息超时后自动重试 3 次，再用纯文本补发 3 次。超时只说明没收到回执，消息可能已经发出去了，bot 又读不到群里的历史消息，无法核对 |
| 看不出收没收到 | 发完消息后，要等 Claude 开始调用工具或开始写字，进度气泡才出现，在此之前群里没有任何反馈 | 群聊不像私聊那样显示已读和输入状态，bridge 也没有回执 |

## 状态消息

| 情况 | 行为 |
|---|---|
| 正常 | 每 30 秒原地更新同一条置顶消息 |
| 这条消息被删了 | Telegram 明确回复消息不存在时，才发一条新的并置顶，同时写日志 |
| 网络失败 | 本次不更新，不发新消息 |
| 异常且连续 3 次没变化 | 停止自动刷新，消息里写明已停止；次数用 `TG_STATUS_PAUSE_AFTER` 调 |
| 状态有变化（比如网络恢复） | 自动恢复刷新 |
| 点「🔄 刷新」 | 立刻刷新一次，停止状态下也有效 |

同一时间只跑一次刷新。比较「有没有变化」只看在线、Telegram、Herdr、会话数、运行中数这五项，不看时间。

## 消息上的 reaction

Telegram 只允许 bot 使用一张固定清单里的表情，每条消息最多一个。❓、❌、⚠️ 不在清单里（10-08 实测返回 `REACTION_INVALID`），所以选用下表。

| 表情 | 表示什么 | 什么时候打上 |
|---|---|---|
| 👀 | bridge 收到了 | 收到消息时，在接回会话、送进会话之前 |
| ✍ | Claude 会话已经接手 | 会话记录里出现这条消息时（消息在排队时保持 👀）；选择题答完、会话继续运行时也改回 ✍ |
| 🤔 | 在等你回答选择题或按键 | 会话停下来等你操作时 |
| 无 | 这一轮的回答已经完整发出 | 最终回答和回传文件全部确认发出后撤掉 |
| 💔 | 没送进会话，或者回答发送明确失败 | 接回会话失败、送进会话失败，或 Telegram 明确拒绝发送时 |
| 😱 | 回答可能发出去了，但没收到回执 | 最终回答或回传文件发送超时时 |

一条消息一直没有 reaction，说明 bridge 没收到，多半是电脑睡着或离线了。bridge 自己的命令（`/new`、`/sessions` 等）有自己的回复，不打 reaction。送进会话的斜杠命令（`/clear` 等）在会话记录里没有可以对上的条目，只在送达失败时标 💔。

**消息和回答怎么对上。** 会话记录里出现你这条消息（直接开始的一轮，或者排队后插进正在跑的一轮）时，它就归入这一轮，这一轮结束时一起结算。会话结束后已经空闲、但还有没对上的消息时，也一并结算，避免一直停在 ✍。

## 发送不重复

| 请求 | 网络失败时 |
|---|---|
| 发消息、发图片、发文件、建话题 | 不重试。结果记为「不确定」 |
| 编辑消息、置顶、设置 reaction 等 | 照旧重试，重复执行结果一样 |
| 任何请求收到 Telegram 的「请稍后再试」（429） | 按要求等待后重试 |

网络失败后不再用纯文本格式补发一遍；纯文本只用于 Telegram 拒绝了 HTML 格式的情况。

进度气泡发送不确定时，这一轮不再发新的进度气泡，避免重复，最终回答照常发送。

## `/resend`

在话题里发 `/resend`，bot 把上一轮回答里没确认发出的部分（文字分段和回传文件）再发一次，全部确认发出后撤掉 😱。上一轮全部确认发出时，回复「上一轮回答已经全部发出」，不重发。上一轮回答只存在内存里，bridge 重启后 `/resend` 无内容可发，回答仍可以在 Herdr 标签页里看到。

## 不做的

- 「正在输入」状态（sendChatAction）。它只持续 5 秒，要不停重发；断网时会多出一批失败请求，reaction 已经能表达同样的信息。
- 自定义表情的 ❓、❌、⚠️。需要在群设置里放开自定义 reaction，Telegram 可能还要求群的助力等级，使用者选了清单里的表情。

## 验收

| 项 | 方法 |
|---|---|
| 断网时不发新状态消息，3 次后停止刷新，恢复后接上 | 替换网络请求的模拟脚本 |
| 状态消息被删后只重建一条 | 同上 |
| 刷新按钮 | 置顶消息上点按钮，看「更新于」时间变化 |
| 发消息超时不重试，记为不确定 | 模拟脚本 |
| reaction 依次变化 👀 → ✍ → 撤掉 | 在真实话题里发一条消息 |
| 选择题时变 🤔，答完变回 ✍ | 真实话题里让会话提一个选择题 |
| 😱 与 `/resend` | 模拟脚本让最终回答超时，再发 `/resend` |
