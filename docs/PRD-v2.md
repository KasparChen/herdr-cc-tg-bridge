# tg-bridge v2 在 Telegram 里管理会话的完整生命周期

状态 CONFIRMED
版本 v2
前版路径 `docs/PRD-v1.md`（CONFIRMED 2026-10-05，保留不改）
依据 2026-10-05 使用者反馈，在 Telegram 里关不掉会话，bot 反复提示会话已不存在、要开新会话，关闭、清理、管理会话都有问题
确认依据 2026-10-05 对话，使用者看过生命周期设计后确认四项取舍全部按推荐执行
定稿日期 2026-10-05

## 结论

v2 给每个话题加了一套完整的会话生命周期。在 Telegram 里可以关闭、重新打开、删除会话，也可以列出全部会话。电脑上已经在聊的会话，可以用 `/tg-bind` 接到 Telegram，在手机上接着用，回到电脑前再接着推进。电脑上的会话断了，话题里只提示一次，再发消息会接着原会话，不会掉进一个没有上下文的新会话。每轮结束时显示上下文占用，置顶消息显示 5 小时、7 天和 Fable 额度。v1 的其余能力不变。

## v1 的问题

下面四条已经复现，证据来自会话记录、bridge 日志和状态文件。

| 问题 | 发生了什么 | 原因 |
|---|---|---|
| 关闭指令落进空白会话 | 在话题里发「删掉这个tab吧」。原窗格已经不在，bridge 先开了一个全新会话，再把这句话发给它。新会话没有上下文，就把自己所在的标签页关了 | 话题对应的窗格不在时，任何消息都会触发开新会话 |
| 在 Telegram 里关不掉会话 | 只能靠会话自己理解「关掉」是什么意思 | bridge 没有关闭会话的命令，话题被关闭、删除时也不做任何处理 |
| 同一条提示反复出现 | 「窗格不见了，发一条消息会自动开新会话」在每次 bridge 重启后都会再发一遍 | 是否已提示只记在内存里，重启就清零 |
| 留下没人管的标签页 | 会话执行 `/exit` 后窗格还在，只剩一个 shell。下一条消息会另开一个标签页，旧的那个一直留着 | 「Claude 已退出」和「窗格已关闭」没有区分 |

另外还有两处同类缺陷，代码里能直接看出来。一是话题被关闭、重新打开、改名时，Telegram 会往话题里发一条系统消息，如果窗格已经不在，这条系统消息也会触发开新会话。二是在 General 里随手发一句话，bot 每次都回整段帮助。

## 会话的状态

每个话题的绑定处于下面五种状态之一。状态和「是否已经提示过」都存在 `state.json` 里，bridge 重启后不会重复提示。

| 状态 | 什么情况下进入 | 话题里看到什么 |
|---|---|---|
| 在线 | 窗格里的 Claude 正在运行 | 正常对话 |
| Claude 已退出 | 窗格还在，Claude 退出了（例如执行了 `/exit`） | 提示一次，附「接着原会话」「开新会话」「关闭话题」三个按钮 |
| 标签页已关 | 在电脑上关掉了这个标签页 | 同上，只提示一次 |
| 已关闭 | 在 Telegram 里发 `/close`，或者在客户端里关闭话题 | 收到一条「会话已结束」，之后不再提示 |
| 已删除 | 话题被删除 | 话题已经不存在，bridge 直接删掉绑定并结束窗格 |

## 在 Telegram 里能做什么

| 在哪里 | 操作 | 效果 |
|---|---|---|
| 任意位置 | `/new 名字` | 新建话题和会话，名字可以是中文 |
| 客户端 | 手动新建话题 | 自动绑定一个新会话 |
| 话题里 | `/close`，或者在客户端里关闭话题 | 结束 Herdr 窗格，关闭话题，聊天记录保留 |
| 客户端 | 重新打开已关闭的话题，或者直接在已关闭的话题里发消息 | 用 `claude --resume` 接着原会话，上下文都在 |
| 话题里 | `/delete`，再点「确认删除」 | 结束窗格，删除话题和全部聊天记录，删除绑定，不可恢复 |
| 客户端 | 删除话题 | bridge 发现后结束窗格并删除绑定 |
| 客户端 | 给话题改名 | Herdr 标签页同步改名，之后不再按会话标题自动改名 |
| 任意位置 | `/sessions` | 列出全部会话、状态、上下文占用和最后活动时间，每个会话一排按钮（关闭或接回或重开，以及删除），名字可以点进对应话题 |
| 电脑上的会话里 | `/tg-bind`，断开用 `/tg-bind off` | 把这个会话接到一个新话题，见下一节 |
| 输入框 | 敲 `/` | 弹出 bridge 的命令菜单 |

会话断了之后再发消息，默认接着原会话。如果原会话的记录文件找不到，就开新会话，提示里也会写明。想要一个干净的新会话，就点提示里的「开新会话」。

删除只有一种，就是结束会话、删除话题和绑定一起做，要再点一次确认。不提供「只解绑、保留话题」的操作，因为一个话题解绑后再接别的会话，前后的聊天记录对不上。被删除的话题会自动发现并清掉绑定，所以也不需要单独的清理命令。

## 把电脑上的会话接到 Telegram

电脑上和手机上用的是同一个会话。在 Telegram 发的消息，会直接输入到电脑上那个会话里，电脑上能看到这条输入和完整回复；绑定期间在电脑上打的字，也会出现在话题的进度气泡里，前面带 🖥。

使用流程如下。

1. 在电脑上的会话里输入 `/tg-bind`。这是一个只能由使用者主动调用的 skill，它运行 `bin/tg-bind`，请 bridge 绑定当前窗格。
2. bridge 用会话标题新建一个话题，先发一张接手卡片，写明会话在哪个 Herdr Space、项目目录、上下文占用和上一轮的问题，再把上一轮的完整回答单独发出。绑定时如果这一轮还没结束，结束后的回答会直接发到话题。
3. 在手机上直接在话题里接着聊。
4. 回到电脑前，在原来的标签页里继续输入即可，不需要切换。

这类会话的规则和 Telegram 里新开的会话不同。在 Telegram 里关闭或删除话题，只断开 Telegram，电脑上的会话继续开着，Herdr 标签页名也不会被改。重新打开话题，或者在已关闭的话题里发消息，会重新连上同一个会话。在电脑上运行 `/tg-bind off` 也是断开。断开后再运行 `/tg-bind`，会重新打开原来的话题，不会再建一个。

只有装了 Herdr 的 Claude hook 之后启动的会话能绑定，否则 bridge 拿不到会话 ID，也找不到会话记录。

## 上下文和额度

| 显示什么 | 在哪里 | 数据来源 |
|---|---|---|
| 当前会话的上下文占用，例如「ctx 43% (430k)」 | 每轮结束时的进度气泡标题行、`/sessions`、接手卡片 | Herdr 记录的会话上下文数，只有装了 hook 的会话才有 |
| 上下文超过 80% 的提醒 | 话题里提醒一次，建议 `/clear` 或开新会话；降到 40% 以下后重新计数 | 同上 |
| 5 小时、7 天额度和重置时间 | 置顶状态消息、`/status`、`/sessions` | Claude Code 传给状态栏的数据，由使用者的状态栏脚本写成 JSON 文件，用 `TG_USAGE_FILE` 指定 |
| Fable 额度 | 同上 | 使用者自己的抓取脚本写的 JSON 文件，用 `TG_FABLE_USAGE_FILE` 指定 |

没有工具调用的轮次不出进度气泡，这一轮就不显示上下文占用。额度数字只在有会话刷新状态栏时更新，所以超过 2 分钟没更新时会注明「更新于几分钟前」。两个额度文件默认不配置，不配置就不显示。

## 防止休眠

bridge 运行期间，supervisor 会启动 `caffeinate -i -s`，阻止 Mac 闲置休眠，接电源时也阻止系统休眠。bridge 停止时它会跟着退出。设 `TG_BRIDGE_CAFFEINATE=0` 可以关掉。合上盖子仍然会休眠，`caffeinate` 不处理合盖。

## 提示怎么防止刷屏

- 会话断开的提示，每次断开只发一次，存进状态文件，重启后不会重发。会话恢复在线后才会重新计数。
- 话题被关闭、重新打开、改名、置顶等系统消息，一律不会触发开新会话。
- 在 General 里发的非命令消息，最多每 10 分钟回一行提示，不再每条都回整段帮助。
- Herdr 连不上的时候，话题里不提示。置顶状态消息会显示 Herdr 异常。
- bridge 发出的每条提示都会写进 `bridge.log`。日志统一使用本地时间，和守护脚本写的行一致。

## 怎么发现话题被删除

Telegram 没有列出话题的接口，话题被删除时也不推送任何事件（已对照 Bot API 10.3 官方文档）。bridge 靠下面两种方式发现。

- 往话题发消息失败，返回 `message thread not found`。
- 主动探测。bridge 启动时、之后每小时一次，以及执行 `/sessions` 之前，把每个话题当前的开关状态重新设置一遍。话题存在时返回 `TOPIC_NOT_MODIFIED`，不会产生任何可见变化；话题不存在时返回 `TOPIC_ID_INVALID`。

实测中，刚删除的话题第一次探测可能仍然返回成功，所以要连续两次都返回「不存在」才算删除。探测时如果因为记录的开关状态有误，真的把话题切换了，bridge 会立刻切回来。结束窗格这类动作只在确认删除后才执行。

## 结构变化

```text
router.ts      只负责分发：命令、系统消息、附件、按钮
   │
   ▼
lifecycle.ts   新增。开会话或接回、绑定电脑会话、关闭、删除、改名同步、列表、话题探测
   │
   ├── session.ts   Watcher 按持久化的状态判断是否提示，每次断开只提示一次
   ├── herdr.ts     新增 paneState（在线 / 已退出 / 已关闭 / 连不上）、paneClose、在原窗格里重启 Claude
   ├── telegram.ts  新增 notice（提示写日志）、topicAlive（话题探测）、发送失败时上报话题已删除
   ├── store.ts     绑定新增名字、终端 ID、关闭时间、是否已提示、最后活动时间、是否电脑会话
   └── usage.ts     新增。解析上下文占用，读取额度文件
```

绑定里记下 Herdr 的终端 ID。Herdr 服务重启后窗格编号可能被重新分配，终端 ID 对不上就当作窗格已关闭，不会把消息发进别人的窗格，也不会误关别人的窗格。

## 验收

下表各项都用本机模拟入口加 bridge 日志验证过（模拟模式下会把发出的消息正文写进日志）。

| 场景 | 通过标准 | 结果 |
|---|---|---|
| 断开只提示一次 | 窗格不在的话题提示一次，重启 bridge 后不再重复 | 通过 |
| 接回原会话 | 窗格不在的话题里发消息，接回的会话记得上一轮做过什么 | 通过 |
| `/close` | 标签页关闭，Telegram 话题关闭，会话 ID 保留 | 通过 |
| 重新打开话题 | 接回原会话 | 通过 |
| `/exit` 之后 | 提示「会话在电脑上退出了」；点「接着原会话」在原窗格里重启，不多开标签页 | 通过 |
| 电脑上关标签页，再在客户端关话题 | 不开新会话，绑定进入「已关闭」 | 通过 |
| 在已关闭的话题里发消息 | 重新打开话题，接回原会话，消息送达并得到回复 | 通过 |
| 话题在别处被删除 | `/sessions` 探测到删除，结束窗格，删除绑定 | 通过 |
| 往已删除的话题发消息失败 | 自动确认删除并清理绑定 | 通过 |
| `/delete` | 点确认后话题、窗格、绑定都被删除 | 通过 |
| 开新会话按钮 | 旧窗格关闭，新标签页里是新会话 | 通过 |
| 中文名字的 `/new` | 正常开出会话 | 通过（v1 实际不可用，见下文） |
| 话题改名 | Herdr 标签页同步改名 | 通过 |
| General 里随手发消息 | 连发两条只回一行提示 | 通过 |
| 命令菜单 | 群里注册了 9 条命令 | 通过 |
| `/tg-bind` | 新话题收到接手卡片和上一轮回答 | 通过 |
| 绑定后两边对话 | Telegram 发的消息得到回复；电脑上直接输入的也出现在话题里，带 🖥 | 通过 |
| 电脑会话的 `/close` 和删除 | 话题关闭或删除，电脑上的会话还在运行 | 通过 |
| 电脑会话断开后发消息或再运行 `/tg-bind` | 重新连上原来的话题，不新建话题 | 通过 |
| 上下文和额度 | 气泡标题行有 ctx；置顶消息和 `/sessions` 有三项额度 | 通过 |
| 防止休眠 | `caffeinate` 跟随 supervisor 运行，父进程退出后断言释放 | 通过 |

手动建话题、改名、`/sessions` 里的关闭按钮、`/delete` 加确认按钮，这几项已经用真实 Telegram 操作验证过。在客户端里关闭、重新打开话题时推送的系统消息格式，以及上下文超过 80% 的提醒，还没用真实操作验证。

## 关键决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 在 Telegram 里「关闭会话」做到哪一步 | 关闭话题，保留聊天记录；彻底删除另用 `/delete`，要点确认 | 关闭可以撤回，删除不行 |
| 是否保留「只解绑」 | 不保留，和删除合并 | 解绑后的话题再接别的会话，聊天记录前后对不上 |
| 电脑会话在 Telegram 里关闭或删除 | 只断开 Telegram，电脑上的会话继续开着 | 会话是使用者在电脑上开的，回到电脑时它应该还在 |
| 在客户端里手动关闭话题 | 等同于 `/close`，同时结束 Herdr 窗格 | 这是使用者最自然的关闭动作；只停转发会让电脑上积累一批以为已经关掉的会话 |
| 会话断了以后再发消息 | 默认接着原会话；想要新会话就点按钮 | 避免控制指令落进没有上下文的新会话。代价是长会话接回时要重新载入上下文，消耗更多 token |
| 话题被删除后 | 结束窗格并删除绑定 | 删除话题表示不再需要这个会话。会话记录文件留在本机，需要时可以在电脑上用 `claude --resume` 找回 |
| 关闭窗格的方式 | `herdr pane close`，不用 `tab close` | 关掉最后一个窗格时标签页会一起关闭；使用者把标签页拆分过时，不会误关其他窗格 |

## 相对前版的变更

- 新增会话生命周期，即本文前面各节。
- 修复 agent 名字。v1 把话题名直接当作 Herdr 的 agent 名字，而 Herdr 只接受小写字母、数字、`-` 和 `_`，所以 `/new 中文名` 一直开不出会话，已有中文标题的话题也无法重新开会话。v2 的 agent 名字固定为 `tg-<话题编号>`，话题名只用作标签页名。开会话失败时，会把刚建的空标签页一起关掉。
- 修复错误读取。Herdr 命令行把错误信息写到 stderr，v1 读不到，所有失败都被当作「没有结果」处理。v2 能区分「窗格不存在」和「Herdr 连不上」。
- 行为变化。v1 在窗格不在时开新会话，v2 改为默认接着原会话。
- 修复回答发不出来。会话里有后台子任务在跑时，Herdr 会一直显示「运行中」，v1 要等状态变成空闲才发最终回答，所以回答会一直扣着。v2 改为看会话记录里的「本轮结束」标记收尾。
- 修复话题卡死。曾有一次发往 Telegram 的请求在连接断开后既不返回也不报错，这个话题此后再也收不到回答。v2 给每个请求加了硬超时；单次检查超过 90 秒就放弃，并写入日志。
- v1 的终局能力、验收标准和不做的事，除上面列出的变化外全部保留。
