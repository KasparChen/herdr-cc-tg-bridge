## 问题与意图

离开电脑时没法继续用本机的 Claude Code。现有的两类远程方案都会丢掉一部分本机环境。

- 官方 Telegram Channels 插件运行在单个会话里，一个 bot 只能绑一个会话。
- Garyx 一类网关在后台起无界面的 `claude --print` 进程，跑的不是桌面上的会话，也没法在电脑上接着用。

目标是让在 Telegram 里操作的就是电脑上那几个 Claude Code 会话本身，记忆、配置、hook、skill 全部照常生效。回到电脑前可以在终端里接着用同一个会话。

## 核心原则与边界

- 会话由 Herdr 管理。bridge 不自己起 Claude 进程，只通过 Herdr 的接口送消息、读状态、发按键。
- 回复从 Claude Code 的会话记录文件读取，不抓屏幕文字。屏幕内容只在等待输入时用来展示。
- 一个 Telegram 话题对应一个会话，绑定关系保存在本地状态文件里。
- 只接管 bridge 自己新建的会话，或者装了 Herdr 的 Claude hook 之后启动的会话。
- 所有个人信息（bot token、群 ID、用户 ID、工作目录、Herdr Space）都放在配置里，代码和文档不写死。
- 只允许白名单里的 Telegram 用户发指令。除此之外没有额外的安全限制，会话的权限模式沿用本机设置。

不做的事如下。

- 私聊话题模式。
- 接管旧会话。
- 同一个 bot 跨多台机器。
- 在 Telegram 里展示 Claude 的思考过程。

## 终局与验收

终局能力如下。

1. 在话题外发 `/new 名字`，新建话题，同时在指定的 Herdr Space 里开一个标签页启动 Claude。
2. 手动新建一个话题，bridge 自动开一个新会话绑上去。
3. 在话题里发的文字、图片、文件都送进对应的会话，图片和文件先存到本地，再把路径附在消息里。
4. 每一轮对话先显示一条可折叠的进度气泡，实时更新；结束后变成「完成」，再单独发出最终回答。
5. 会话这一轮新建的交付文件自动发回话题。会话也可以用 `tg-send` 命令主动发送任意文件。
6. 会话弹出选择题时，话题里出现按钮，点一下就把答案送回会话。其他等待输入的情况发屏幕截取，用 `/keys` 回应。
7. 会话标题生成后，同步成话题名和 Herdr 标签页名。
8. 桥接状态在下面三个地方可见。
   - Telegram 置顶消息，带最后更新时间。
   - `/status` 命令。
   - Herdr Space 上的状态标签。它带过期时间，bridge 停掉后会自动消失。
9. 进程崩溃后自动重启。断网后持续重试，网络恢复后自动连上。
10. macOS 登录后自动启动（LaunchAgent），守护脚本本身被杀时由 launchd 重新拉起。

验收标准如下。

| 场景 | 通过标准 |
|---|---|
| 新建会话 | `/new` 和手动建话题都能在 10 秒内回「新会话已就绪」，Herdr 指定 Space 里多出对应标签页 |
| 文字往返 | 带工具调用的一轮对话里，气泡实时更新，收尾显示完成，最终回答完整 |
| 图片和文件上行 | 发一张图让会话描述，会话读到的是本地文件 |
| 文件下行 | 让会话生成一张 png 和一份 pdf，两者都出现在话题里 |
| 选择题 | 点按钮后会话收到对应选项 |
| `/clear` | 清空后的下一轮回复照常回到同一话题 |
| 状态显示 | 杀掉 bridge 进程后，置顶消息变红，Herdr 状态标签在过期时间内消失，supervisor 在 5 秒内拉起新进程并恢复绿色 |
| 断网恢复 | 断网 1 分钟再恢复，不用人工干预就继续收消息 |
| 登录自启 | 杀掉守护脚本后，launchd 重新拉起，旧的 bridge 进程不残留，1 分钟内恢复在线 |

## 结构与职责

```text
Telegram 群（话题模式）
      │  长轮询 getUpdates / sendMessage / editMessageText / sendDocument
      ▼
┌──────────────────────── bridge 进程（Bun） ────────────────────────┐
│ telegram.ts   Bot API 客户端，含超时、重试、文件上下行                  │
│ router.ts     收消息、命令分发、附件落地、按钮回调                      │
│ session.ts    每个话题一个 Watcher，轮询状态、读会话记录、驱动渲染      │
│ transcript.ts 增量读取会话记录 jsonl，解析成事件                        │
│ render.ts     tg-fold 气泡、Markdown 转 HTML、表格转列表、分块           │
│ outbox.ts     判断哪些文件要回传，发送                                  │
│ status.ts     心跳、置顶状态消息、Herdr 状态标签、/status               │
│ store.ts      state.json，存更新偏移量和话题绑定                     │
│ herdr.ts      Herdr CLI 封装                                         │
│ control.ts    本机 HTTP，负责 tg-send 接收、健康检查、测试模拟入口       │
└───────────────┬───────────────────────────────┬──────────────────┘
                │ herdr CLI（socket）            │ 读 ~/.claude/projects/*/<session>.jsonl
                ▼                               ▼
        Herdr Space 里的 Claude 会话  ──写──►  会话记录文件
                ▲
                │ tg-send <文件>（读环境变量 HERDR_PANE_ID）
          会话内的 Claude
```

数据流分四条。

- 上行。Telegram 消息 → router → `herdr agent prompt <pane> <文字>`。附件先下载到 `inbox/<话题>/`，再把路径附在文字后面。
- 下行。Watcher 每秒查一次 `herdr agent get` 的状态，并增量读取会话记录。工具调用进气泡，文字暂存。状态从「运行中」变成「空闲」时收尾，把气泡改为完成，发最终回答，按规则回传文件。
- 阻塞。状态变成 `blocked` 时，如果会话记录里最后一个工具调用是选择题，就把选项发成按钮，否则发屏幕截取。按钮回调转成 `herdr pane send-keys`。
- 状态。每 30 秒更新一次心跳。在线要两条同时成立，一是最近一次 `getUpdates` 成功在 90 秒内，二是 Herdr socket 可连。

状态归属如下表。

| 状态 | 归属 |
|---|---|
| 话题与会话的绑定、Telegram 更新偏移量 | `state.json`（bridge 独占） |
| 会话进程和会话状态 | Herdr |
| 会话内容 | Claude Code 会话记录 |

## 关键决策与未决假设

| 决策 | 选择 | 理由 |
|---|---|---|
| 会话运行方式 | Herdr 里的交互式会话 | 能保证和电脑上用的是同一个会话；后台无界面进程做不到 |
| 回复来源 | 会话记录 jsonl | 结构化，有工具调用和标题；屏幕文字会被终端排版打乱 |
| 会话 ID 来源 | Herdr 官方 Claude hook | 会话启动时自动上报；`/clear` 后新 ID 即时上报 |
| 进度呈现 | 复刻 tg-fold，一轮一张折叠气泡加一条最终回答 | 沿用已经验证过的阅读习惯 |
| 文本格式 | Telegram HTML | 和 MarkdownV2 渲染效果一样，转义规则更简单；解析失败时改发纯文本 |
| 文件回传 | 两种机制并用。Write 工具新建的文件按扩展名自动回传，其余用 `tg-send` 显式回传 | 见下面的机制上限 |
| 自动回传白名单 | 图片、pdf、Office 文档、压缩包、html、csv、音视频。不含 `.md` 和 `.txt`（可配置） | md 和 txt 多是 memo 和草稿，自动发出去会刷屏 |
| 在线判定 | 最近一次轮询成功在 90 秒内，且 Herdr 可连 | 只看进程活着会误报在线，断网时进程还在，但收不到消息 |

机制上限有三条。

- 会话用 Bash 跑脚本生成的文件（例如 python 画图）不经过 Write 工具，会话记录里看不到文件路径，只能靠会话主动调用 `tg-send`。bridge 新建的会话会在系统提示里加一句说明，让会话知道这个命令。
- 电脑睡眠或关机时 bridge 发不出任何消息。置顶状态消息的时间戳停止更新，是唯一的信号。
- Bot API 下载文件上限 20MB，上传 50MB。超限时在话题里提示。
- Herdr 服务由使用者打开 Herdr 时启动，bridge 不代为启动。bridge 若拉起 Herdr 服务，服务会成为 bridge 的子进程，bridge 重启时所有会话会被一并结束。

待验证的假设有两条。

- Herdr 状态标签在界面上的显示位置还没确认，需要使用者看一眼。
- 一轮对话超过 4096 字的最终回答按段落分块，代码块跨块时可能断开格式。断开时改发纯文本，内容完整保留。
